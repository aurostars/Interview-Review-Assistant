# 面试问题筛选与编辑功能设计

## 概述

在 AI 分析完成后，新增一个"问题筛选"环节，让用户快速选择保留或排除特定问题，并支持修改问题/回答文本后对单个问题重新分析。

## 核心流程

1. 用户上传录音或粘贴文本 → AI 一次性分析全部内容
2. 分析完成后自动弹出筛选弹窗，列出所有识别的问题
3. 用户勾选要保留的问题，可编辑问题/回答文本
4. 确认后：被排除的问题在详情页不显示；被编辑的问题逐个调 AI 重新分析
5. 详情页顶部提供"筛选问题"按钮，随时可重新打开筛选弹窗

## 数据结构变更

在面试数据对象中新增两个字段：

```js
interview = {
  // ...现有字段...
  excludedQuestions: [],   // 被排除的问题索引数组，如 [1, 3]
  editedQuestions: {}      // 被编辑过的问题，key 是索引字符串，value 是 {question, answer}
}
```

- `excludedQuestions`: 详情页渲染时跳过这些索引的问题
- `editedQuestions`: 记录用户修改的文本，编辑后触发单个问题的 AI 重新分析，结果覆盖 `analysis.questions[index]`
- 两个字段持久化到 JSON 文件，刷新后不丢失

## 筛选弹窗 UI

### 结构

- 标题："筛选面试问题"
- 问题列表，每项包含：
  - 左侧 checkbox（默认全选）
  - 问题序号
  - 问题文本（点击进入编辑态）
  - 回答文本（折叠显示，展开后可编辑）
- 底部操作栏：
  - 左侧："已选 X / 共 Y 题"
  - "全选/全不选" 快捷操作
  - "确认" 按钮

### 交互

- 取消勾选的问题视觉上变灰
- 点击文本进入编辑态（textarea），失焦退出编辑
- 编辑过的问题显示"已修改"标记
- 确认后保存状态，对编辑过的问题调 AI 重新分析

### 触发时机

- 首次分析完成后自动弹出（在处理进度弹窗关闭后）
- 详情页顶部"筛选问题"按钮点击时打开

## AI 重新分析单个问题

### Prompt 设计

复用 `Analyzer` 类，新增 `reanalyzeSingle(question, answer, jobType, jd)` 方法：
- 输入：修改后的问题文本 + 回答文本 + 岗位方向 + JD
- 输出：单个 question 对象（与现有 questions 数组元素格式一致）
- 结果直接覆盖 `analysis.questions[index]`

### 用户体验

- 有编辑的问题时，弹窗显示"正在重新分析第 X 题..."进度
- 多个编辑问题串行分析
- 全部完成后关闭弹窗，刷新详情页

### 错误处理

- 单个问题分析失败时保留原有分析结果
- Toast 提示"第 X 题重新分析失败"
- 不阻塞其他问题

## 详情页变更

### 渲染

- 问题列表跳过 `excludedQuestions` 中的索引
- 侧边栏目录（TOC）同步跳过被排除的问题
- Summary 保持原 AI 返回的整体评价，不重新生成

### 入口

- 详情页顶部信息区域增加"筛选问题"按钮
- 打开与首次相同的筛选弹窗，预填当前状态

## 涉及文件

| 文件 | 变更 |
|------|------|
| `app/js/app.js` | 新增筛选弹窗渲染/交互逻辑，修改 startAnalysis 流程，修改详情页渲染 |
| `app/js/analyzer.js` | 新增 `reanalyzeSingle` 方法 |
| `app/index.html` | 新增筛选弹窗 HTML 结构 |
| `app/css/main.css` | 筛选弹窗样式 |

## 不做的事

- 不支持新增问题（只能修改已识别的）
- 不重新生成 summary
- 不改变现有分析 prompt 或整体分析流程

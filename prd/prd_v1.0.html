1. 需求背景

现状问题

应届生在求职期间通常面临10场左右的面试。当前绝大多数求职者在面试结束后完全依赖记忆进行复盘，存在以下问题：

  • 遗忘快：面试结束后数小时，具体问答细节已大幅遗忘，无法精准回顾
  • 无法量化：不清楚自己在哪些维度表现好、哪些差，改进无据可依
  • 缺乏纵向追踪：多场面试之间的共性弱点和高频考点无法被系统发现
  • 改进低效：即使知道"答得不好"，也不知道具体应该怎样改进表达

市场空白

目前市面上的面试相关产品集中在"面试题库"和"模拟面试"领域，缺乏一款针对真实面试录音进行结构化分析、质量评价和改善建议的工具。

3. 用户与场景

用户画像

维度描述
身份在校应届生或刚毕业的求职者
求职阶段正在密集面试期（1-3个月内完成约10场面试）
面试形式一对一面试为主，线上/线下均有
技术背景各方向均有，上传时通过岗位标签区分
设备手机录音 + 电脑端查看分析
使用周期求职期工具，拿到offer后停止使用

核心用户场景

  1. 面试后即时上传：小王刚面完一场后端面试，掏出手机把30分钟录音上传到网站
  2. 查看纪要和建议：几小时后打开电脑，阅读结构化纪要，查看每个回答的评价和改进示例
  3. 多轮复盘：同一家公司二面前，回顾一面的改善点，重点准备薄弱项
  4. 规律洞察：面了5家公司后，查看跨面试分析，发现自己在"项目复杂度表达"上总是丢分

5. 详细方案

以下为各核心功能模块的详细交互逻辑和业务规则。原型确认后将补充iframe原型切片。

5.1 录音上传与信息标注

交互流程

  1. 用户点击"上传面试录音"按钮
  2. 弹出上传区域，支持拖拽或点选文件
  3. 文件选择后，展示信息填写表单：
    • 公司名称（文本输入，支持历史匹配）
    • 岗位标签（下拉选择：后端/前端/算法/产品/设计/运营/其他）
    • 面试轮次（下拉：一面/二面/三面/HR面/终面）
    • 面试日期（日期选择器，默认今天）
  4. 点击"开始分析"提交

业务规则

  • 支持格式：m4a, mp3, wav, aac, ogg
  • 单文件上限：500MB（约覆盖2小时录音）
  • 公司名称必填，岗位标签必填，轮次默认"一面"
  • 同一公司+同一轮次不可重复上传（提示确认覆盖）

5.2 语音转录与说话人分离

处理流程

  1. 文件上传至云端存储
  2. 调用ASR服务进行语音转文字
  3. 进行说话人分离（Speaker Diarization），标记为"面试官"和"候选人"
  4. 对低置信度片段标记⚠️图标，显示"此处转录可能不准确"
  5. 完成后通知用户（站内通知 + 可选邮件）

业务规则

  • 说话人默认识别为两人（一对一场景）
  • 通常提问方为面试官，回答方为候选人；系统根据对话模式自动判断角色
  • 置信度阈值：低于0.7的片段标记为低置信度
  • 预计处理时间：录音时长的1-3倍（30分钟录音约30-90分钟完成）

5.3 结构化纪要生成

输出结构

每场面试纪要包含以下层级：

  • 面试概览：公司、岗位、轮次、日期、总时长、问题总数
  • 问答列表：每个问答对包含：
    • 面试官问题原文
    • 追问链路（如有）：标明哪些问题是基于前一个回答的深入追问
    • 考察意图标签（如：系统设计能力、沟通表达、项目经验深度）
    • 候选人回答原文
    • 回答评价：✅ 好的部分（绿色高亮）+ ❌ 不足部分（红色高亮）+ 原因说明
    • 改进回答示例（可展开/收起）
  • 整体总结：本场面试的整体表现评语、top3亮点、top3待改进

5.4 多轮规律分析

触发条件

  • 用户累计完成分析的面试 ≥ 2场 时，自动生成规律分析
  • 每新增一场面试完成分析后，自动更新规律洞察

分析维度

分析类型输出内容展示形式
共性弱点 在多场面试中重复出现的薄弱维度 弱点列表 + 出现次数 + 具体问答链接
高频考点 被多个公司/多轮面试重复考察的知识点或能力维度 考点热力图 + 频次排序
改善趋势 同一维度在时间线上的表现变化 折线图（表现随面试场次的变化）

筛选能力

  • 按岗位标签筛选（只看后端面试的规律）
  • 按公司筛选（只看某公司多轮面试的变化）
  • 按时间范围筛选

5.5 数据组织与导航

公司维度视图（默认首页）

  • 左侧：公司列表卡片（按最近面试日期排序）
  • 右侧：选中公司后展示各轮次面试卡片
  • 每个面试卡片显示：日期、岗位标签、问题数、整体评价摘要

岗位标签筛选

  • 顶部标签栏：全部 | 后端 | 前端 | 算法 | 产品 | ...
  • 切换标签后，公司列表和规律分析均按标签过滤

7. 异常与边界

场景处理策略
录音文件格式不支持上传时校验，提示支持的格式列表
录音文件过大（>500MB）上传时拦截，提示文件大小限制
录音内容过短（<1分钟）允许上传但提示"录音较短，分析结果可能有限"
转录质量极差（>50%低置信度）完成后提示"录音质量较差，建议检查关键内容"
无法区分说话人回退为不分角色的纯文本转录，标记为"角色未识别"
处理超时（超过3小时未完成）邮件通知用户处理异常，提供重试按钮
同公司同轮次重复上传弹出确认弹窗，用户可选覆盖或取消
网络中断导致上传失败支持断点续传；失败后保留草稿，提示重试
